# NFT Collectibles — handoff to Bayu / submission repo

## Context

Raka requested four NFT-only vehicles, explicitly separate from the playable Tier 1–4: Minecraft minecart, white SPPG box truck, burger car, SpongeBob boatmobile. Assets are prepared locally in the same project at `frontend/public/collectibles/`; no contract or existing game behavior was modified.

## Available now

- An independent catalogue with IDs 1–4. These IDs do not imply minted tokens or tiers.
- SPPG/burger procedural Three.js models with embedded label textures; portable GLB + PNG artwork.
- Minecart/boatmobile original source names, authors, CC BY 4.0 attribution, PNG preview images and official Sketchfab embeds. The source GLBs are not downloaded: Sketchfab requires login for the official downloads.
- `drafts/1.json`–`4.json`, each with the exact source credits. No production token URI has been set; the public domain is still undecided.
- An unauthenticated asset workbench at `/collectibles/index.html`, with no mint, ownership or transaction behavior.
- SHA-256 asset manifest generated by `scripts/collectibles/verify.mjs`.

## Contract boundary

The deployed `CarNFT.sol` has `MAX_TIER=4`, fixed tier prices/supplies, tier qualification, backend vouchers and tier-based tokenURI. Do not point its baseURI at these collectible files: that would replace the existing tier artwork. This work adds neither a fifth tier nor a new purchase method.

A separate contract/collection must define its own asset mapping and issuance rules. Bayu needs a product decision on: ERC-721 vs ERC-1155, supply per design, free claim/paid mint/reward, transferability, who may mint and how duplicate claims are handled. Those decisions have not been invented in the asset implementation.

If private/admin minting is chosen, enforce issuer authorization in the contract, not the UI. If user claims are chosen, bind allowed account, collection/design, nonce and expiry in the contract/signed authorization and enforce replay protection. If minting is deliberately public, keep read access public and state the public mint rules explicitly. Add cross-user/unauthorized tests to the contract implementation at that time.

## Before minting

1. Download the two original Sketchfab archives through the official logged-in download flow if local 3D files are required for those designs. Existing PNG-only NFT artwork can be prepared independently, but do not advertise original GLB files as bundled.
2. Raka reviews model appearance manually. Export automation here creates assets; it does not verify visual quality.
3. Choose permanent public HTTPS hosting. The `prepare.mjs` script writes absolute image/model URLs into `metadata/`; see public README for usage.
4. Bayu provides separate contract address, final ABI, chain ID, metadata mapping, supply and issuance rules.
5. Only after the contract/data interface is agreed should FE add an ownership/mint page and backend indexing. Nothing is minted by this asset work.

## Submission migration

Copy the new `frontend/src/nft`, `frontend/scripts/collectibles`, `frontend/public/collectibles` and these context documents into the new submission repository after comparing its latest tree. No secrets or .env files belong to this asset bundle. Existing tier assets in `frontend/public/cars` remain separate.
